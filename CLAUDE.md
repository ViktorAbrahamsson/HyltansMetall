# Hyltans Metall Website

Sand-casting foundry in brons och mässing (Gnosjö, est. 1926). Swedish copy, English identifiers.
**Most site copy originates from the real site at hyltansmetall.se** (mainly `/om-foretaget`, `/tillverkningen` and `/specialtillverkning`) — the history, the process steps and the pull-quote are the owner's own words, signed Håkan Abrahamsson. Writing new copy is fine now, but match that register: plain and factual, the owner's voice, not marketing. **Propose any new or rewritten copy in the chat and wait for the owner's approval before editing a file** — never land a wording change unasked, not even a small one.
Vite 8 + React 19 + React Router 8 (the `react-router` package; `react-router-dom` is gone) + TypeScript 7 + SCSS modules. Node ≥ 22.22 (Router 8 needs it); `.nvmrc` pins 24 for Netlify. Static site, no CMS — content lives in `src/data/*.ts`. No 3D/Three.js — the owner explicitly does not want the 3D model; it and every Three.js package are gone from the repo.

## Hosting

The old Netlify preview (hyltansmetall-687f.netlify.app) is gone; `public/_redirects` and `public/_headers` stay so the site could move back. Verified on the live preview: Brotli, a year's immutable cache on `/assets`, the security headers, a 308 from `/om-foretaget`.

## Commands
- Dev: `npm run dev`
- Build: `npm run build` — `tsc`, the client `vite build`, an SSR build of `src/entry-server.tsx` into `dist-ssr/`, then `node scripts/prerender.mjs` (writes the pages, deletes `dist-ssr/`). The Sass `legacy-js-api` deprecation warnings in the log are harmless.

## Prerendering
- Every public page is rendered to static HTML at build time: `dist/index.html`, `dist/om-oss.html`, `dist/produkter/tomtar.html`... plus `dist/404.html`. Crawlers, link previews and AI agents get each page's full text and own head tags without running JS; the browser then **hydrates** that markup.
- `App.tsx` has no router: `main.tsx` wraps it in `BrowserRouter`, `entry-server.tsx` in `StaticRouter`. The page list is `routes` in `entry-server.tsx` (product categories come from `productCategories` automatically). **A new top-level page must be added there and to `public/sitemap.xml`.**
- `#root` carries `data-prerendered-path`; `main.tsx` hydrates only when it equals the current path, otherwise renders fresh (`404.html` has no attribute; an unknown product slug redirects). `npm run dev` has no prerendered markup and always renders fresh.
- **Head tags without a library.** React 19 hoists `<title>`, `<meta>` and `<link>` into `<head>` wherever they render, so `Seo.tsx` renders them directly (react-helmet-async was removed). On the server `renderToString` puts them first in its output; `entry-server.tsx` splits that leading run off as `head`, and `scripts/prerender.mjs` swaps it in between `<!--seo-start-->` and `<!--seo-end-->` (keep those markers), marking each tag `data-prerendered`. `main.tsx` removes every `[data-prerendered]` tag before React renders, since React then inserts its own; otherwise each tag would appear twice. React 19 also adds a `<link rel="preload" as="image">` for every `fetchPriority="high"` image, which lands in the same block.
- **Render code must be server-safe**: no `window`/`document`/`matchMedia` outside effects and event handlers, and nothing that differs between build and visit (random values, dates) in markup — or hydration mismatches. Use `useIsomorphicLayoutEffect` (`src/hooks/`) instead of `useLayoutEffect`. The footer year uses `suppressHydrationWarning`, since the build year can lag.
- `scripts/prerender.mjs` **inlines the stylesheet** into every page as a `<style>` (about 7 KB gzipped) instead of a render-blocking `<link>`: with real mobile throttling that took first paint on Om oss from 2.13 s to 1.40 s. The CSS file stays in `dist/assets` unused. The script also fills the `<!--font-preload ... -->` marker in `index.html` with preload links for the two fonts every page paints first. Keep that marker too.
- `npm run preview` serves the prerendered files like Netlify, except that it answers unknown paths with `index.html` instead of `404.html` (the client still shows the 404 page).
- **npm only.** `package-lock.json` is the one lockfile. A stale `pnpm-lock.yaml` from the Three.js days made Vercel install with pnpm and fail; don't add another package manager's lockfile.

## Performance
- **Fonts are self-hosted** through `@fontsource-variable/fraunces` (opsz + opsz-italic) and `@fontsource-variable/inter` (wght), imported in `main.tsx`; no request goes to Google (faster first paint, no visitor IP to a third party). The families are `'Fraunces Variable'` / `'Inter Variable'` (tokens in `variables.scss`, plus the hardcoded stack in the `eyebrow` mixin).
- **Metric-adjusted fallback faces** (`Inter Fallback` from Arial, `Fraunces Fallback` from Georgia, in `main.scss`) sit second in each stack, so the swap to the web font barely moves text. Without them Inter re-wrapped the Om oss intro on phones and pushed the page 33px. The overrides come from `@capsizecss/metrics` (not a dependency; numbers are in the comment) — recompute if a font changes.
- `vite.config.ts` splits `node_modules` JS into a `vendor` chunk (cached across content deploys). CSS is kept out of it on purpose, or the font CSS becomes a second render-blocking stylesheet.
- The Instagram feed is fetched only when its section comes within ~1000px of the viewport (IntersectionObserver); the placeholder frames hold the height until then.
- The home quote's backdrop is a plain `<img srcSet>` (not a CSS background, not `Figure`), so phones get `natt-800`.
- **Lighthouse** (Nov 2026, local `npm run preview`, after the React 19 upgrade and quality-80 images): desktop 99–100 on every page; mobile performance 83–92 simulated, accessibility/best practices/SEO 100. Real throttling: Om oss first paint = LCP 1.29 s, home 1.79 s. React 19 + Router 8 made the vendor chunk 87 KB gzipped (was 60). Weakest page is Tomtar (real LCP ~4 s): its first item photo (112 KB) shares the connection with the fonts, the JS and the Fraunces **italic** (80 KB at top priority on every page, used only for the footer's "grundat 1926" and the home quote). Judge mobile timings with `--throttling-method=devtools`: the default simulated mode models the inlined CSS and preloaded fonts badly and reports ~3 s LCP where the real throttled LCP equals first paint (~1.4 s). Its "properly size images" notes are the 400/800 width ladder against a 412px × 1.75 DPR test phone, not wrong `sizes`. Run it from a scratch folder (`npm i lighthouse`), not as a project dependency.
- **PageSpeed Insights (Nov 2026)** on the Vercel preview found what local Lighthouse with a GPU cannot: **27–34 s Total Blocking Time** on the home page, from the hero ember canvas (`shadowBlur` on every ember, every frame, rasterised in software on Google's GPU-less test machines and on many cheap phones). Reproduce with Lighthouse and `--chrome-flags="--headless=new --disable-gpu"`: 40 s TBT before the fix, 0 ms after (desktop score 69 → 100). Always test animation changes that way. The remaining PSI notes are expected: "blocked from indexing" (preview noindex), ~40 KiB unused JS (React/Router), and "improve image delivery" (Lighthouse compares to CSS size; quality 80 is the owner's choice). The anonymous PSI API quota runs out quickly; read the report on pagespeed.web.dev instead.
- **Measure in a top-level page with the Browser pane visible.** Measuring inside an iframe reported CLS 0.5 from the body's default 8px margin (a paint before the stylesheet applied) that never happens top-level; a hidden pane throttles paint timings.

## Hard SCSS rules (violations have caused real bugs)
- `vite.config.ts` injects `@use 'variables' as v; @use 'mixins' as m;` into **every** SCSS file. Never add those `@use` lines yourself. `src/styles/mixins.scss` must not reference `v.$*` (circular load).
- `generateScopedName: '[local]'` → CSS-module class names are **global**. Every class in every `*.module.scss` must be globally unique: always prefix with the file's block name (`.contact-page__form-input`, never `.inner`, `.form`, `.grid`). Hyphenated names need bracket access in TSX: `styles['about-page__lead']`.
- **Never reference a module class that has no styles.** An empty rule (`.x {}`) compiles to nothing, so `styles['x']` is `undefined` and the literal class `undefined` lands in the HTML (it was on every page until Nov 2026). Add the class to the TSX only once it has a rule; sections already carry their global `<name>-block` class. Check a build with `grep -o 'class="[^"]*undefined' dist/*.html`.
- The `grain()` mixin does not set `position` — the caller must already be positioned.
- `backdrop-filter` creates a containing block for `position: fixed` descendants (this trapped the mobile menu overlay inside the header once). **The header is one solid colour at every scroll position — no blur, no scrolled state.** Don't reintroduce `backdrop-filter` on it: the full-screen `.overlay` would be confined to the header's own box again.
- **`m.focus-ring()` draws the outline 3px *outside* the element, so it is invisible inside anything that clips.** A link filling a card with `overflow: hidden` (`.card__link`) and a full-width dropdown row (`.nav__submenu-link`) both lost their ring entirely — focusable but with no indicator, which looks exactly like not being focusable. Use `m.focus-ring($color, -4px)` in those cases.
- Verify focus with **real Tab presses**. Calling `.focus()` from a script does not reliably trigger `:focus-visible` in Chrome and reports no outline at all, which sends you chasing the wrong bug.
- A module class and a global one have equal specificity, so source order decides and the global usually wins. `section.product-category__intro-block` is qualified with the element for exactly this reason — it has to outrank `.block`'s padding.

## Conventions
- BEM inside modules; page sections get a global `<name>-block` class plus `.block` (+ `--alt`/`--paper`/`--dark`) and `.container`/`-sm`/`-xs`. Everything full-width shares one 1200px `$container-width` — including the header's inner bar — so edges line up on large screens. (There was a `-lg`/1440px variant; it was removed for exactly that reason.)
- `src/components/layout/ScrollToTop.tsx` resets scroll on route change (the router otherwise keeps the old position). It deliberately skips `POP` so back/forward restores where the visitor was.
- **Every page sets its head through `<Seo title description? />`** (`src/components/layout/Seo.tsx`): it adds the canonical URL, og:/twitter tags and the share image. Never render a second `<title>` or description elsewhere — React 19 hoists every one it meets. `index.html`'s copies (between the seo markers) only serve `npm run dev` and carry `data-prerendered`. **Each content page has its own share image**: `public/og/<page>.jpg` (1200×630 JPEG), with `public/og-image.jpg` (the bronze angels) as the default for the home page, the 404 and any page without one. `node scripts/make-og-image.mjs` builds them from the processed WebPs (`cover` crops; the square card photos use `contain` over a blurred copy so tomte caps and candles stay whole; Produkter is the angel and tomte cards side by side). The path → image map and each `og:image:alt` (the photo's own alt text, verbatim) are `SHARE_IMAGES` in `Seo.tsx`; keep it in step with the script's `JOBS`. A noindex page gets no `og:url`. The Organization JSON-LD in `index.html` repeats `company.ts` facts by hand — update both. **Add every new public URL to `public/sitemap.xml`.**
- Unknown paths render `NotFoundPage` (`path="*"`, last route): "Sidan finns inte", `noindex`, no canonical. It is prerendered as `404.html`, which the host serves with a real 404 status.
- A skip link ("Hoppa till innehållet", `.skip-link` in `main.scss`) is the first focusable element in `App.tsx`; it targets `<main id="main" tabIndex={-1}>`. Keep that id and tabindex.
- **Machine-readable copies of the site text** — keep them in step when copy, contact facts or pages change: `public/llms.txt` (summary for AI agents: page list with each page's meta description, product facts, process steps — all verbatim site text; the tomte specs are left out because their matching to the old site isn't confirmed), `public/site.webmanifest` (`icon-192/512.png` come from `scripts/make-favicons.mjs`), `public/sitemap.xml` and the JSON-LD.
- `RouteFocus.tsx` moves focus to the new page's `h1` after each client-side navigation (screen readers announce the page; also closes a header dropdown held open by `:focus-within`). Keep exactly one `h1` per page, inside `<main>`.
- The mobile menu makes `main` and `footer` `inert` while open, and Escape closes it and returns focus to the menu button.
- Contrast (WCAG AA): `$color-ink-soft` (#5F574D) and `.label`'s `$color-verdigris-deep` pass 4.5:1 on every light surface including sand-deep; plain `$color-verdigris` does not — don't use it for small text on light. Product card titles are `h3` by default and `h2` on /produkter (`headingLevel`), so no page skips a heading level.
- **Every content page opens with the shared `.page-intro` / `.page-intro__lead` pattern** (in `main.scss`): the `h1` centred with the lead centred beneath it. Use it rather than styling a per-page lead. Kontakta oss's lead and phone number come from the owner's own text (the "Texter ny hemsida" document).
- Mobile tuning: `.block` padding is 3rem on phones, 4rem from md and 6rem from lg (two blocks meet with both paddings: 96/128/192px between sections; it was 4/5/8rem until Nov 2026, too airy, and 6rem on phones before that). `$font-size-display` floors at 2rem / 10vw so "Specialtillverkning" fits a 320px screen; headings also carry `overflow-wrap: break-word; hyphens: auto` as a safety net. `.page-intro__lead` trims its half-leading with a negative `lh` margin so intros sit evenly. The hero's "Scrolla" cue is hidden below md (it ran through the 1926 numeral); from md it is a button that smooth-scrolls the next block to just under the fixed header (only the label+arrow stack is clickable — its wrapper spans the container and keeps pointer-events: none). The mobile menu starts under the header rather than centring.
- **Scroll reveal** (`src/components/layout/ScrollReveal.tsx` + `.reveal--*` in `main.scss`): every direct child of `main section.block > .container`, plus anything with `data-reveal`, fades up as it enters the viewport; a child that is a grid or `<ol>` is split so its items stagger in. Nothing per page to wire. **Full-width images never animate** (owner's request): an image-only element as wide as its container is skipped, and the home banner has no `data-reveal`. **Controls never animate either**: the Instagram slider (arrows) and its dots carry `data-no-reveal`; put that attribute on any future carousel or pagination. Only content below the fold is hidden (first paint / LCP untouched), `aria-hidden` decor is skipped, and it is off under reduced motion. It animates `translate`, not `transform`, and removes its classes once landed so elements get their own transitions back. Verify it with the Browser pane *visible* — a hidden pane never fires IntersectionObserver, so everything below the fold stays invisible.
- The footer is pinned to the bottom of the window on short pages: `#root` is a `min-height: 100svh` flex column and `main` is `flex: 1 0 auto` (in `main.scss`). Don't wrap the app in another element between `#root` and `main`/`footer` without carrying that over.
- The page scrollbar is bronze on sand-deep: `scrollbar-color` on `html` (Chrome/Edge 121+, Firefox; it inherits into every scroll area) plus `::-webkit-scrollbar` rules for Safari. The dark mobile menu overrides it with bronze on coal.
- The Instagram slider shows arrows at every width (inside the screen edge on phones) and one dot per resting position (posts minus tiles in view, plus one), the current one bronze.
- **Mouse users can drag the Instagram slider** (`useDragToScroll.ts` beside it). Mouse only (`pointerType === 'mouse'`); touch and pen keep the browser's native swipe. While dragging, `instagram-feed__track--dragging` switches off scroll snapping; on release the row settles on the nearest resting position (a quick flick carries ~180 ms further) and snapping returns when it stops. A press that moves under 6px is a click and opens the post; a real drag swallows the click that follows. The grab cursor shows only on `(hover: hover) and (pointer: fine)`. `tileStep` lives at module level so the hook's listeners are not re-attached on every render.
- There is **no eyebrow label above an `h1`** on a content page; those were removed. The landing page keeps its hero and section labels.
- Section headings carry no `01`/`02`/`03` batch stamps, and product cards carry no `Nr xx` — both removed on request, along with the `Steg xx` stamp. The only numbering left is the outline numeral on manufacturing steps (the process sequence itself) and the slot number on an unphotographed product item. `.batch-stamp` still exists in `main.scss` but nothing uses it.
- **Every content page has a breadcrumb bar** (`src/components/layout/Breadcrumbs/`), not the home page or the 404. It is rendered **once in `App.tsx`, between `<Header>` and `<main>`**, not inside the pages: it is `position: sticky` under the fixed header, and a sticky element only sticks within its parent, so inside `<main>` it slid away when the footer came up. In the flow it sits at the top behind the header and takes its own 53px; `<main>`'s header padding then lands page content right under it. `.breadcrumbs + main > section.block:first-child` trims the first block's top padding, so a page with crumbs must start with a `section.block`. **It hides while scrolling down and returns on scrolling up** (headroom): a passive, rAF-throttled scroll listener toggles `breadcrumbs--hidden` (translateY(-100%) puts it wholly behind the 76px header), always shown near the top, reset on navigation, and `:focus-within` brings it back for keyboard users. A hairline shadow fades in once content scrolls beneath it (scroll-driven animation, no JS). `html` has `scroll-padding-top` (header + 3.5rem) so focused elements stop below the bar. The **trails live in `TRAILS` in `Breadcrumbs.tsx`** (a new content page needs an entry; categories come from `getCategoryBySlug`, published only). They follow the **menu**, not the URL: Kontakta oss is Start › Om oss › Kontakta oss. It also emits a schema.org `BreadcrumbList`. Crumb text uses `$color-ink`; hover uses `$color-bronze-deep` (`$color-bronze` is 2.87:1 on sand). Test the scroll behaviour with real wheel scrolling in a fronted, visible tab: the Browser pane dropped scroll events for scripted `scrollTo` jumps.
- **Navigation loading bar** (`src/components/layout/NavigationProgress/`): a 3px molten-bronze bar across the top of the window (above the header) on every in-site navigation, not on the first load. Every page's code is already loaded, so it waits for the **images in view** on the new page (load or error), at least 350 ms and at most 4 s, then fills and fades. Driven by class changes on a ref, never React state, so it does not re-render the page. `aria-hidden`: RouteFocus announces the page.
- All colors/spacing/sizes via tokens in `src/styles/variables.scss`; responsive only via `m.respond-to(sm|md|lg|xl)`, mobile-first.
- **Focus: one ring everywhere** — `m.focus-ring($color, $offset: 3px)`: 2px solid, 3px outside; `#B07A2E` on light backgrounds, `#D9A24B` on dark ones (header, footer, `.block--dark`, the mobile menu, the skip link over the header). Inside anything that clips (product cards, Instagram posts, dropdown rows) pass `-4px` to draw it inside. `.btn`/`.btn--ghost` use the light colour by default and the dark one inside `.block--dark`. Form fields use the same ring (no glow of their own). Never write a bespoke `outline` — use the mixin. A global `prefers-reduced-motion` block in `main.scss` collapses all transitions/animations.
- **Hover: one language, documented at the top of the Links section in `main.scss`.** Every hoverable element shows it, and `:focus-visible` shows the same state as `:hover` (write `&:hover, &:focus-visible`). Text links on **dark**: text brightens to cream + a bronze-light underline (never a colour change *to* bronze — bronze text marks the current page). Text links on **light**: text and underline turn `$color-bronze-deep` (plain bronze fails AA on sand). Buttons: the brass wipe. Photo links (product cards, Instagram posts): the photo zooms to 1.04 (cards also get a bronze frame and bronze-deep title). Icon controls (menu button, arrows, dots, social icon, scroll cue): icon/border turns bronze. Logo: the name warms to bronze. Form fields: bronze border. The global `a` hover is `:where()`-wrapped (zero specificity) so it never decides a component's hover: until Nov 2026 it was the only "hover" the footer e-mail/phone had, setting the bronze they already were, and `.header .nav__link` made the menu links white at rest so their cream hover changed nothing. Verify hovers with real mouse hovers (computer `hover`, then read computed styles after the transition, ≥1s) and focus with real Tab presses, reading the outline synchronously in a `focusin` handler.
- Design system "Sand & Brons": motif classes `.label`, `.molten`, `.ghost-numeral`, `.batch-stamp`, `.btn`/`.btn--ghost`/`.btn--light` in `src/styles/main.scss`. Fonts: Fraunces + Inter, **self-hosted** (see Performance).
- **`.ghost-numeral` has a fixed em box** (2.03em × 0.85em, text right-aligned), sized to "1926" in Fraunces 500. All of them are anchored by their right edge, and as shrink-to-fit boxes they jumped when the font swapped in (CLS 0.088 on PageSpeed mobile, where Georgia is missing so the adjusted fallback does not apply). Resize the box if a numeral ever shows other text.
- The hero stays typographic/generative: a hand-rolled canvas ember field (`src/components/common/Hero/EmberField.tsx`, no deps, respects prefers-reduced-motion) + molten glow + ghost numeral. Do not reintroduce Three.js or a 3D model — the owner explicitly does not want it (the old `public/models/ljusstake.glb` was deleted).
- **EmberField draws pre-rendered glow sprites** (one small canvas per colour, made once) with `drawImage`; never go back to `shadowBlur` or per-frame filters on that canvas. Motion is time-based (`step` from the rAF timestamp, clamped), not frame-counted, which ran 2.5x too fast on 144 Hz screens.

## Images
- **`src/assets/images/manifest.ts` is generated — never edit it by hand.** It is the only way images enter the app: `import { images } from '@/assets/images/manifest'`, then `images['process/04-gjutning']`. Each entry carries `src`, `srcSet` (several widths), `width`/`height`, and `blur` (a ~20px placeholder inlined as a data URI). Keys are literal-typed, so a typo is a build error.
- Never `import x from '.../foo.webp'` directly and never use `/images/...` URL strings — that bypasses srcset and the placeholder.
- Always render through `src/components/common/Figure/Figure.tsx`: `<Figure image={...} alt="" ratio="landscape" sizes="..." />`. It reserves its box from the ratio, shows the blur *behind* the photo, and lays `grain()` over the top.
- **Never gate the `<img>` behind an opacity/JS "loaded" flag.** An `<img>` with no data is already transparent, so the blur underneath does the placeholder work by itself and the photo paints the instant it decodes. The old version held `.fig__img { opacity: 0 }` until React flipped state, which forced a visible placeholder on *every* image — cached ones included — and would have stranded a photo invisible if a load event were ever missed.
- Pass `priority` for images in view on first paint (sets `loading="eager"` + `fetchpriority="high"`); everything else stays lazy. Currently the first product card, the first manufacturing step and the first item on a category page. Without it the LCP image is fetched late and at low priority. `Figure` passes `fetchPriority` (React 19 supports the prop natively; the React 18 lowercase workaround is gone).
- Measure loading on the **preview** build (`npm run preview`, port 4173), never `npm run dev`: in dev, Vite requests every image URL module separately (`foo.webp?import`, ~49 extra round-trips) which makes loading look far worse than production, where the same page is 4 requests total. Only `hyltans-dev` exists in `.claude/launch.json`; start preview by hand.
- **Always pass a real `sizes`.** It defaults to `100vw`, which over-fetches badly inside a 3-column grid — the browser picks the candidate before it knows the layout. On phones, an image inside a `.container` is `calc(100vw - 3rem)` (1.5rem side padding), not `100vw`; portrait gallery tiles are `calc((100vw - 4.5rem) / 2)`. Only truly full-bleed images (home banner, quote backdrop) use `100vw`.
- `src/assets/images/inbox/` is the raw dump for unprocessed originals. It is gitignored (repo `.gitignore` + `.git/info/exclude`) and lives in the main checkout, not in worktrees.
- `scripts/process-images.mjs` (dev dep: `sharp`) turns inbox originals into the sorted WebP assets at **quality 80** (`QUALITY`; the blur placeholder has its own) **and rewrites `manifest.ts`**: `INBOX=<path> node scripts/process-images.mjs`. Its `JOBS` table is the source of truth for crop shape and rotation; `SHAPES` defines each ratio's width ladder.
- Widths above the source's own width are skipped so nothing is upscaled, and the source's native width is added as an extra rung when it falls between two — several photos are only ~620px wide once rotated, and the earlier pipeline was silently upscaling them to 1400px.
- The portrait, landscape, square and strip ladders include a **640** rung (400/640/800[/1200]): a content-width photo on a 1.75–2x phone needs ~600–640px, and the old 400 → 800 jump over-fetched by ~35% there.
- **EXIF orientation is not trustworthy in this photo set.** Most files carry `orientation=6`, but a few were cropped by an editor that rotated the pixels and kept the tag, so applying it turns them 90°. The `rotate` flag per job is set from *looking at the output*, not from the tag. Always eyeball regenerated images before committing.
- Three product categories in the data: Änglar, Malmljusstakar, Tomtar. **Malmljusstakar is `hidden: true`** until after release (no product names or photos yet): `productCategories` is the published list and everything reads it, so the nav, cards and sibling links skip it and `/produkter/malmljusstakar` redirects to `/produkter`. Remove the flag to publish it. The card grids size their columns from the card count (`--cards` inline), so two categories fill the row. - Each category also has `items` (the individual products) in `src/data/products.ts`: one ängel, three tomtar, three malmljusstakar — that last count is a **placeholder guess**. The grid follows the array, so adding or removing a product needs no code change. An item with no `image` renders a frame at the category's own ratio, so dropping a photo in later shifts nothing.
